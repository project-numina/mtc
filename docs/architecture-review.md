# Architecture review

Reviewed `arch/review` at `b27a0185`, with the pinned Lean and Mathlib v4.35.0 sources. This is an architecture review, not a formal verification of the paper or an independent check of every proof. References below are to this snapshot. The companion plan gives a complete file mapping and a migration protocol.

## Findings, in priority order

1. **The public entry points and documentation describe a different library.** `README.md:5` and `FORMALIZATION.md:3` name the absent `PropertyF/Main.lean` and a theorem with `StandardInputs`; `FORMALIZATION.md:10` says essential constructions are missing. In the current tree `PropertyF/Ground/Final.lean:91` proves the frozen `TargetStatement`, and `TargetAudit.lean:138` checks its declaration and dependency cone. `AXIOMS.txt:1` records old names and types. Rewrite the documentation against actual declarations and preserve the previous ledger only as explicitly dated history. This matters more than cosmetic renaming because a reader currently receives the wrong theorem and assumptions.

2. **The statement is a foundational dependency but is housed under a proof-workstream name.** `Ground/Target.lean:31` defines fusion categories and lines 62–112 define the dimensions and target; `Ground/Fusion/Simples.lean:2` must import the entire target to obtain that basic API. The file is frozen and must stay byte-for-byte unchanged. Plan around it with a compatibility boundary; do not silently claim that physical moves alone decouple this dependency.

3. **The top-level proof is short but its mathematical roadmap is incomplete.** `Ground/Final.lean:13` names three results, and the proof at lines 91–122 constructs the pivotal structure, center fusion and spherical structures, balancing, nondegeneracy and a centralizer result before invoking an arithmetic reduction. It does not explain why those inputs prove the paper's theorem or point to the overlap bound, Galois rigidity, symmetric integrality, or the relevant paper lemmas. Add a reader-facing roadmap and named intermediate bridges; preserve the existing final theorem name and type while the target remains frozen.

4. **Layer boundaries are real but obscured by back-edges and mixtures.** For instance `Dimensions/DoubleDualUnitTensor.lean:4` imports `Integrate.CharacterReality` and line 5 imports `Modular.SMatrix`; `Dimensions/ENOMatrices.lean:6` does likewise. This does not create an import cycle, but it prevents treating the whole `Dimensions` directory as a low layer. `MonodromyTensorCap.lean:3` imports `SMatrix` for a braided-rigid calculation, coupling a general-looking theorem to fusion-level material. Separate generic duality, trace and matrix facts from fusion-specific ENO arguments and braided monodromy. Treat folder layers as a proposed end state, not an assertion about today's DAG.

5. **Paths and namespaces retain agent ownership rather than mathematical concepts.** The sibling directories `Centre`, `CentreBundle`, `CentreCabling`, `CentreCalculus`, `CentreDimensions`, `CentreInduction`, `CentreIntegrate` and `CentreModular` are difficult to browse together. `CentreDimensions/PivotalTwist.lean:13` is actually in namespace `PropertyF.Ground.Dimensions`, while `CentreCabling/ImageCore.lean:175` also declares `CentreCalculus` results. `Integrate/CharacterReality.lean:28` combines representative equivalences with matrix characters. Mathlib has `CategoryTheory/Monoidal/Center.lean` and `CategoryTheory/Monoidal/Rigid/{Basic,Functor}.lean`, and uses `Center`; reorganize under mathematical subtopics and use that spelling. Maintain stable namespaces separately from paths during migration.

6. **The generic pivotal API is useful but manually reconstructs a functorial structure.** `Dimensions/Pivotal.lean:22–63` builds right-dual isomorphism maps, a double-dual tensorator and a componentwise natural/monoidal isomorphism. Mathlib already defines `CategoryTheory.rightDualFunctor` in `Monoidal/Rigid/Functor.lean:57`, `ExactPairing` in `Rigid/Basic.lean:78`, and dual comparison isomorphisms in that file. Compare and construct a monoidal double-dual functor with a monoidal natural isomorphism before upstreaming; do not assert Mathlib already has the full pivotal API. `rightDualObject` at line 34 merely wraps `Xᘁ`. An explicit `PivotalStructure` is reasonable because multiple choices coexist; `IsSpherical p` at line 78 is naturally a proposition on that chosen structure. A typeclass may be a convenience layer only after resolving instance coherence, not a forced replacement.

7. **Trace and centrality definitions overlap and their characteristic API is uneven.** `Definitions.lean:66–73` defines quantum traces of an isomorphism, while `Dimensions/Pivotal.lean:50,68–74` defines endomorphism traces; identity comparison lemmas at lines 88–103 make the relationship explicit. `Calculus/PartialTrace.lean:23` and `CentreCalculus/LeftTensorTrace.lean:32` provide opposite partial traces. `Centre/Basic.lean:69` defines center centrality, while `Modular/SMatrix.lean:34` defines double braiding. Centralize shared definitions and prove compatibility lemmas before eliminating any wrapper, especially those referenced by the frozen statement. In the sampled pivotal/trace files, naturality and trace identity/linearity lemmas mostly lack `simp` or `reassoc` attributes; Mathlib's `Monoidal/Center.lean:63–86` marks half-braiding naturality and morphism compatibility. Add selected oriented identity, projection and reassociation rules with regression checks, not blanket simp attributes on cyclicity or tensor expansions.

8. **The frozen API is credible but represents a narrower, choice-heavy interface.** Detailed assessment follows below. In particular `IsFusionCategory` requires braiding even for general fusion theory (`Ground/Target.lean:31–33`), and an inverse function of the unit algebra map appears before its bijectivity theorem (lines 82–86). These are design limitations, not evidence that the theorem is false.

9. **Audit coverage is valuable but is coupled to the library root and manual inventories.** `PropertyF.lean:2` publicly imports `ProjectAudit`, which `import all`s private bodies across the project; the root additionally lists many individual modules. `scripts/check-audit-imports.py:8–26` only checks missing `import all` lines in two manually maintained files, and `TargetAudit.lean:153–157` rejects axioms outside the allowed set but does not itself require all three to appear. The current observed list is exactly three. `DependencyAudit.lean:56–86` deliberately trusts named upstream packages and fails closed on uninspected project modules and foreign implementations; this is a meaningful additional safeguard, not a replacement for reviewing definitions. Keep both gates while moving their physical modules, update name-based forbidden lists/fixtures and all inventories atomically, and explicitly compare the printed axiom set if exact equality is required.

10. **Maintenance material is stale or placed in the production tree.** `Target.lean:15–17,82–84` says obligations are pending even though the current proof and `Integrate/UnitScalar.lean:24–46` establish relevant facts; because the file is frozen, document the correction externally until an approved revision. `Integrate/TargetAudit.lean:133–135` says it is not in the ordinary build while its own comment describes an earlier state; it is indeed a separate audit target, but the theorem exists. `Dimensions/MultiplicityDefect.lean:237–239` calls a compatibility unproved; check it against the later conditional extension in `DefectExtension.lean:187–199` before rewriting the precise claim. `PLAN.md:41–49`, `AXIOMS.txt`, `ground/*/{STATUS,DEPENDS}.md`, the style TSVs and launcher/log are historical working artifacts. Classify them as historical, regenerate, or remove in a separately reviewed maintenance change; do not erase useful provenance blindly. `README.md:21` suggests cache retrieval and different cores; do not execute it on this shared machine.

The root has depth 25 edges, `Final` 23, and `Target` 1. `Final` reaches 108 other project modules; the only excluded project files are the three audit modules. ## Frozen target assessment

`Target.lean:28–40` provides finite-dimensional Hom spaces, simple unit, and finite semisimplicity by actual biproduct decompositions; this is substantive mathematical data rather than a numerical axiom bundle. It fixes the field to ℂ and includes abelian, linear, rigid and braided structure. Standard fusion categories do not intrinsically require braiding, so later factor an unbraided `IsFusionCategory` from `BraidedFusionCategory`; also consider a general field and unbundled category type with a bundled wrapper for quantification. Such a change changes the frozen statement and requires explicit approval. The current bundled structure records instances and supports the intended quantification.

`rank` and `simples` use classical choices (lines 62–65), and `fusionMatrix` uses actual simple Hom dimensions (68–69). `fpSimple` uses the complex spectral radius converted from `ℝ≥0∞` to `ℝ` (71–73); its finiteness and agreement with the positive fusion character are proved in `Fusion/Agreement.lean:102–106,437`, so `toReal` is not an arbitrary dimension field. Representative equivalence is available at `Integrate/CharacterReality.lean:28`; expose a direct theorem for independence of global FP and categorical dimensions under changing representatives rather than making users assemble it.

The braiding supplies `doubleDualIso` through Mathlib's exact pairing (77–80). The squared norm and global dimension (88–94) use genuine quantum trace composites; choice independence on simples is proved in `Dimensions/GroundNorm.lean:57–85`, and `unitScalar` is proved to agree with an algebra equivalence in `Integrate/UnitScalar.lean:24–46`. The use of `Function.invFun` before its bijectivity proof makes rewriting and reading awkward, but no extra field is assumed. A future version should use an established algebra equivalence and package invariant definitions after the relevant lemmas. The braided isomorphism is not asserted to be a pivotal monoidal isomorphism.

`HasPropertyF` in `Definitions.lean:28–57` uses the subgroup generated by concrete adjacent braidings on `n+2` strands, an appropriate finite-image formulation provided the usual braid relations/action are connected explicitly; document or prove that bridge if presenting it as literally an Artin-group representation. The missing zero/one-strand cases are trivial. `GaloisConjugate` (97–106) is a semilinear braided monoidal equivalence for an automorphism of ℂ, rather than an abstract numerical conjugacy; same universe parameters for source and witness are a formal restriction to evaluate in a future revision. `PseudoUnitary` is equality of intrinsic and FP global dimensions, and `WeaklyIntegral` (`Definitions.lean:59–61`) means equality with an integer. This matches the intended formulation under the library's fusion-category assumptions. Full equivalence to every convention in the paper and all choice-independence statements has not been independently reconstructed in this review.

## Upstream candidates, ranked by readiness

Readiness concerns extraction and dependency quality, not verified upstream acceptance.

1. **Small generic lemmas**: `Fusion/Simples.lean:20–32` (nonzero mono and exact pairing), `Integrate/CharacterReality.lean:28–40,54–70` (representative equivalence and eigenvectors), and `Fusion/Agreement.lean:33–70` (positive matrix eigenvectors). Extract individually with minimal imports, check for existing lemmas and generalize assumptions. The current parent files pull in much more than their statements.
2. **Rigid and pivotal trace basics**: `Dimensions/Pivotal.lean`, `Trace.lean`, `DualCoherence.lean`, and general portions of `BiproductTrace.lean` and `Calculus/PartialTrace.lean`. First align dual functors and monoidal natural isomorphisms with Mathlib, decide explicit versus class interface, and build a characteristic simp/reassoc API. Work naturally belongs next to `CategoryTheory/Monoidal/Rigid`, `Preadditive` and trace infrastructure.
3. **Center structure**: generic portions of `Centre/Basic.lean`, `Abelian.lean`, and `Rigid.lean`, with `CentreInduction/ForgetDual.lean`; these extend Mathlib's actual `CategoryTheory.Center`, not a competing center. Split the heavy files, lower hypotheses from braided fusion where possible, and check instance overlap and universe behavior. Full center fusion and induction need significantly more infrastructure.
4. **Fusion rules and FP dimension**: `Fusion/{Simples,Multiplicity,Reciprocity,SpectralIntegral,Agreement,ObjectDimension}.lean`, after disentangling `Target`, braid-specific dependencies, and matrix lemmas. A general fusion ring / semisimple category interface and explicit representative invariance are prerequisites. Reuse Mathlib matrix spectrum, eigenspace, charpoly and Schur APIs (`SpectralIntegral.lean:4–9`, `Simples.lean:3`) rather than replacing them.
5. **Center induction, pivotal positivity and modularity**: `CentreInduction/*`, `Modular/*` and center modular files contain valuable theorems but need a broad stable fusion/semisimplicity library, modular category definitions, and substantial generalization; `Vafa.lean` is especially large. These are research-scale upstream projects, not ready isolated PRs.
6. **Paper-specific**: `Final.lean`, `Integrate/ActualCenterReduction.lean`, overlap/three-strand estimates, Galois rigidity, centralizer saturation and project audits belong in this project. Extract independent algebra, braid or matrix lemmas where worthwhile; their current module placement does not establish generality.
